## 1. Purpose of M2.6

Milestone M2.6 introduces the Team Base System, a core gameplay mechanic that establishes a permanent base location for every team.

This system ensures that gameplay follows a triangular loop instead of a simple gather-deliver loop:

TEAM BASE → WORLD → SPAWN PLATFORM → TEAM BASE

Without a team base mechanic, players could remain near the spawn platform after their first delivery and wait for objectives to become solvable. The Team Base System forces teams to return to the world after every delivery cycle, maintaining exploration, risk, and movement across the map.

The base also acts as the verification zone for objective and task completion, ensuring that progress is confirmed only when the entire team has regrouped.

This milestone introduces:

- permanent team base anchors
- base ownership and tracking
- banner-based base markers
- base presence verification
- base completion requirements for objectives and tasks

The Team Base System must exist before the Objective Lifecycle Engine (M3), because objective completion logic depends on base verification.

---

## 2. Team Base Creation

Team bases are created at run start, immediately after team scatter deployment (M2.5).

For each team:

1. The team is teleported to its scatter location.
2. A team banner is automatically placed at that position.
3. The banner position becomes the base center for that team.

The base center is stored as:

team_base {
team_id
center_position
base_radius
}

This data must persist as part of the run state.

---

## 3. Team Banner

The banner acts as the physical marker and anchor of the team base.

Banner properties:

- The banner color matches the team color.
- The banner cannot be destroyed.
- The banner cannot be moved.
- The banner cannot be replaced.
- The banner cannot be exploded.
- The banner cannot be pushed by pistons.

The banner is a permanent world object during the run.

If the banner block is removed by any means (for example chunk rollback or corruption), the system must restore it automatically using the stored base center position.

---

## 4. Base Area Definition

Each base defines a circular area around the banner.

Example:

base_center = banner_position
base_radius = configurable (example: 10 blocks)

The base area is defined as a vertical cylinder spanning the entire world height.

This means base membership checks ignore the Y coordinate.

A player is considered inside the base if:

distance_2D(player_position, base_center) ≤ base_radius

This approach avoids problems with:

- terrain height differences
- caves or cliffs
- vertical positioning edge cases

---

## 5. Base Ownership Rules

Each base belongs to exactly one team.

Rules:

- Only players belonging to that team count toward base presence checks.
- Enemy players may enter the base area.
- Enemy presence does not affect base verification.

This preserves PvP possibilities while keeping ownership rules simple.

---

## 6. Objective Completion Verification

Objectives now require two phases of completion.

Step 1 — Delivery

Players deliver items to the spawn platform.

The system records:

DELIVERY_REGISTERED

Items are removed from the game.

However, the objective is not yet completed.

Step 2 — Base Confirmation

The objective is considered complete only when:

all ONLINE players belonging to the team
are inside their team base area

Offline players are ignored.

When this condition becomes true, the system triggers:

OBJECTIVE_COMPLETED

This ensures that teams must regroup at their base before objective progress is finalized.

---

## 7. Task Verification Rules

Tasks must also be verified inside the team base area.

Examples:

Craft Tasks

Items must be crafted inside the base area.
Crafting outside the base does not count.

Gather Tasks

Gathered items are counted only when the player carrying them enters the base area.

This prevents instant gather completion anywhere in the world.

Smelt Tasks

Furnaces used for smelting must be inside the base area.
Smelting outside the base does not count.

---

## 8. Base Presence Verification

The system must provide a verification method:

areAllOnlineTeamMembersInBase(team_id)

This method returns true when:

every ONLINE player belonging to the team
is inside the team base area

Offline players are ignored.

This method is used by:

- objective completion logic
- task completion verification
- delivery confirmation logic

This data must survive:
